# ⚠️ Telegram AI Gateway · Limitations

Документ описывает известные ограничения проекта Telegram AI Gateway и обходные пути. Симптомы эксплуатации и диагностика по шагам — [operations.md](operations.md), Troubleshooting.

## 📡 1. Telegram API ограничения

### Длина сообщения

**Ограничение:** Максимальная длина сообщения в Telegram: 4096 символов.

**Решение в проекте:** Сообщения длиннее 4096 символов разбиваются на части.

**Ограничение решения:**
- Каждая часть нумеруется (Часть 1/N)
- Разбиение происходит по границам слов
- Может разорвать контекст в середине предложения

### Rate Limits

**Ограничение:** 30 сообщений в секунду в один чат.

**Влияние:**
- При отправке нескольких частей подряд возможен rate limit
- Не влияет на обычное использование (один пользователь = один запрос)

**Решение:** Между отправками частей добавляется минимальная задержка. Retry для отправки в Telegram не реализован — при блокировке отправки пользователь просто не получает часть; проверка логов на ошибки Telegram API.

### Bot API ограничения

- Размер файла: 50 MB, фото: 10 MB
- Размер сообщения: 4096 символов, caption: 1024 символа

**Влияние:** Проект использует только текстовые сообщения, поэтому актуально ограничение 4096 символов. Если пользователь заблокировал бота — ошибка отправки не влияет на другие прогоны (continue on fail).

## 🤖 2. GigaChat API ограничения

### Token Lifetime

**Ограничение:** Access token живёт ~30 минут; в проекте токен запрашивается на каждый запрос — дополнительный HTTP-вызов на каждый прогон.

**Возможное улучшение (не в MVP):** кэширование токена с проверкой expiration time и reuse в течение 30 минут.

### Rate Limits

**Ограничение:** Определяется тарифом GigaChat API. При высокой нагрузке возможен rate limit (не влияет на обычное использование — один пользователь = один запрос).

**Решение:** Retry не реализован — при ответе 429 пользователь получает сообщение «Превышен лимит запросов… Попробуйте через минуту».

### Model ограничения

**Ограничение:** Модель GigaChat-2-Max имеет ограничения на контекст: промпт обрезается до 5000 символов, текст статьи — до 12000. Длинные статьи усекаются.

### Недетерминированность генерации

**Ограничение:** GigaChat может генерировать разный контент для одной статьи: температура (даже 0.1) даёт вариативность, результат зависит от интерпретации промпта.

**Статус:** Ожидаемое поведение модели; детерминированность не гарантируется. Для максимально стабильного результата — температура 0 и ужесточение промпта.

### Ошибки авторизации

**Симптом:** Бот отвечает «Ошибка авторизации в сервисе. Обратитесь к администратору.»

**Причины и обход:**
- Неверный `client_id` / `client_secret` или истёкший срок — проверить credentials на developers.sber.ru
- Неверная Base64-кодировка: `echo -n "client_id:client_secret" | base64`
- Scope `GIGACHAT_API_PERS` должен быть активен

**Статус:** Требует правильной настройки credentials (см. [credentials-setup.md](credentials-setup.md)).

### Сбои GigaChat (500/502/503)

**Симптом:** «Сервис временно недоступен». Причины — перегрузка API, технические работы. **Обход:** при устойчивом сбое — повторить позже.

## 🛠️ 3. n8n ограничения

### Execution Mode

**Ограничение:** Workflow работает в режиме `regular` (не `queue`): выполнение блокирует worker, одновременных выполнений ограниченное количество.

**Возможное улучшение (не в MVP):** переключение в `queue` mode с Redis для очереди.

### Database

**Ограничение:** Execution history хранится в PostgreSQL — при большом количестве выполнений база растёт, n8n потребляет память.

**Решение:** встроенная настройка n8n для автоматической очистки execution history; периодический перезапуск контейнера.

### Режим работы: только Webhook

**Ограничение:** polling-режим неработоспособен. Telegram Trigger при активации workflow всегда регистрирует webhook в Telegram API, а Telegram принимает только HTTPS-адреса — при пустом `WEBHOOK_URL` активация завершается ошибкой (подтверждено Deployment Validation 2026-09-16).

**Решение:** развёртывание с HTTPS-доменом и `WEBHOOK_URL` ([Deployment Guide](deployment_guide.md), §6–7).

## 🗺️ 4. Workflow ограничения

### Извлечение текста

**Ограничение:** Не все статьи корректно извлекаются.

**Причины:**
- Разная структура HTML на разных сайтах
- Динамическая загрузка контента (JavaScript)
- Защита от парсинга (CAPTCHA, rate limits)

**Решение:** Несколько CSS-селекторов в `Extract Article`.

**Ограничение решения:**
- Работает не на всех сайтах
- Может извлекать мусор (навигация, реклама)
- Не работает с JavaScript-рендерингом

**Обходной путь:** добавить новые CSS-селекторы в `Extract Article`; использовать сайты с простой HTML-структурой.

### Очистка текста

**Ограничение:** Очистка может удалить важную информацию или оставить мусор.

**Причины:** Regex-паттерны могут быть слишком агрессивными или мягкими; stop markers не покрывают все случаи; разные форматы статей.

**Решение:** Стоп-маркеры для типичных разделов (Теги, Хабы, Ссылки).

**Обходной путь:** добавить stop markers в `Clean Text`, ужесточить regex, использовать сайты с чистой структурой.

## 🌐 5. Сетевые ограничения

### VPN требования

**Ограничение:** В некоторых сетях требуется системный VPN: блокировка Telegram API, GigaChat API или целевых сайтов.

**Ограничение решения:**
- Пользователь настраивает VPN самостоятельно
- Браузерный VPN не работает для Docker — требуется системный
- Альтернатива — VPS в доступном регионе

### HTTPS для webhook

**Ограничение:** Webhook требует HTTPS; self-signed сертификаты Telegram не принимает.

**Ограничение решения:** требуется доменное имя, публичный IP и настройка DNS; сертификат — Let's Encrypt (или reverse proxy Caddy). Альтернативы нет — polling неработоспособен (см. «Режим работы: только Webhook» выше).

## 📊 6. Производительность

### Время выполнения

**Типичное время:** 5-30 секунд (факторы: размер статьи, скорость GigaChat API, скорость сети).

**Обходной путь (оперативно):** уменьшить `LIMIT_TEXT_LENGTH` и `LIMIT_PROMPT_LENGTH`; проверка скорости сети и нагрузки GigaChat API. Для больших статей ожидание 30+ секунд — ожидаемое поведение.

## 🔐 7. Безопасность

### Credentials

**Ограничение:** Credentials хранятся в PostgreSQL в зашифрованном виде — не в plain text, но могут быть извлечены при доступе к базе.

**Решение:** ограничение доступа к PostgreSQL и логам; credentials в логи не пишутся.

### Rate Limiting

**Ограничение:** Нет rate limiting для пользователей — один пользователь может отправить много запросов.

**Возможное улучшение (не в MVP):** rate limiting по chat_id, очередь обработки запросов.

## 💡 8. Сводка обходных путей

| Ситуация | Обходной путь |
|----------|---------------|
| Статья извлекается с мусором | Добавить stop markers в `Clean Text`, новые селекторы в `Extract Article` |
| Статья не извлекается | Выбрать источник с текстовым контентом, без JavaScript-рендеринга |
| Разные посты для одной статьи | Температура 0, ужесточить промпт |
| Долгое выполнение | Уменьшить `LIMIT_TEXT_LENGTH` / `LIMIT_PROMPT_LENGTH` |
| Rate limit GigaChat | Подождать ~1 минуту (пользователь получит подсказку) |
| Высокая нагрузка | Queue mode n8n, кэширование токена, load balancer |
| Webhook не работает | HTTPS + домен + `WEBHOOK_URL` (порт 443); активация без него невозможна |
| Потребление памяти n8n | Очистка execution history, периодический перезапуск |
