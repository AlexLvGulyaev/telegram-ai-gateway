# Limitations

Документ описывает известные ограничения проекта Telegram AI Gateway.

## Telegram API ограничения

### Длина сообщения

**Ограничение:** Максимальная длина сообщения в Telegram: 4096 символов.

**Решение в проекте:** Сообщения длиннее 4096 символов разбиваются на части.

**Ограничение решения:**
- Каждая часть нумеруется (Часть 1/N)
- Разбиение происходит по границам слов
- Может разорвать контекст в середине предложения

### Rate Limits

**Ограничение:** 30 сообщений в секунду в один чат.

**Влияние:**
- При отправке нескольких частей подряд возможен rate limit
- Не влияет на обычное использование (один пользователь = один запрос)

**Решение:** Между отправками частей добавляется минимальная задержка.

### Bot API ограничения

**Ограничения:**
- Размер файла: 50 MB
- Размер фото: 10 MB
- Размер сообщения: 4096 символов
- Размер caption: 1024 символа

**Влияние:** Проект использует только текстовые сообщения, поэтому ограничение 4096 символов актуально.

## GigaChat API ограничения

### Token Lifetime

**Ограничение:** Access token живёт ~30 минут.

**Влияние:**
- Token запрашивается для каждого запроса
- Дополнительный HTTP запрос на каждый вызов GigaChat

**Возможное улучшение (не в MVP):**
- Кэширование токена
- Проверка expiration time
- Reuse токена в течение 30 минут

### Rate Limits

**Ограничение:** Определяется тарифом GigaChat API.

**Влияние:**
- При высокой нагрузке возможен rate limit
- Не влияет на обычное использование (один пользователь = один запрос)

**Решение:** Retry с exponential backoff.

### Model ограничения

**Ограничение:** Модель GigaChat-2-Max имеет ограничения на контекст.

**Влияние:**
- Максимальная длина промпта: ~5000 символов (установлено в проекте)
- Длинные статьи усекаются

**Решение:** Текст статьи обрезается до 12000 символов, промпт до 5000 символов.

## n8n ограничения

### Execution Mode

**Ограничение:** Workflow работает в режиме `regular` (не `queue`).

**Влияние:**
- Выполнение блокирует worker
- Ограниченное количество одновременных выполнений

**Возможное улучшение (не в MVP):**
- Переключение в `queue` mode
- Использование Redis для очереди

### Database

**Ограничение:** Execution history хранится в PostgreSQL.

**Влияние:**
- При большом количестве выполнений база растёт
- Необходима периодическая очистка

**Решение:** n8n имеет встроенную настройку для автоматической очистки.

### Webhook vs Polling

**Polling (по умолчанию):**
- Плюсы: Проще в настройке, не требует HTTPS
- Минусы: Большая нагрузка на API, медленнее реакция

**Webhook:**
- Плюсы: Быстрее реакция, меньше нагрузка
- Минусы: Требует HTTPS, сложнее в настройке

**Решение:** Оба режима поддерживаются, webhook рекомендуется для production.

## Workflow ограничения

### Извлечение текста

**Ограничение:** Не все статьи корректно извлекаются.

**Причины:**
- Разная структура HTML на разных сайтах
- Динамическая загрузка контента (JavaScript)
- Защита от парсинга (CAPTCHA, rate limits)

**Решение:** Использование нескольких CSS-селекторов для разных типов статей.

**Ограничение решения:**
- Работает не на всех сайтах
- Может извлекать мусор (навигация, реклама)
- Не работает с JavaScript-рендерингом

### Очистка текста

**Ограничение:** Очистка текста может удалить важную информацию.

**Причины:**
- Regex-паттерны могут быть слишком агрессивными
- Stop markers могут не покрывать все случаи
- Разные форматы статей

**Решение:** Стоп-маркеры для типичных разделов (Теги, Хабы, Ссылки).

**Ограничение решения:**
- Работает не на всех сайтах
- Может оставить мусор
- Может удалить важный контент

### Генерация поста

**Ограничение:** GigaChat может генерировать разный контент для одной статьи.

**Причины:**
- Температура модели (даже 0.1 даёт вариативность)
- Разная интерпретация промпта
- Ограничения модели

**Решение:** Низкая температура (0.1) для консистентности.

**Ограничение решения:**
- Результаты не полностью детерминированы
- Разные запуски могут дать разный результат

## Сетевые ограничения

### VPN требования

**Ограничение:** В некоторых сетях требуется системный VPN.

**Причины:**
- Блокировка Telegram API
- Блокировка GigaChat API
- Блокировка целевых сайтов

**Решение:** Документирование требования VPN в setup.md.

**Ограничение решения:**
- Пользователь должен самостоятельно настроить VPN
- Браузерный VPN не работает для Docker
- Требуется системный VPN

### HTTPS для webhook

**Ограничение:** Webhook требует HTTPS.

**Причины:**
- Telegram требует HTTPS для webhook
- Self-signed сертификаты не принимаются

**Решение:** Использование Let's Encrypt или Caddy.

**Ограничение решения:**
- Требуется доменное имя
- Требуется публичный IP
- Требуется настройка DNS

## Производительность

### Время выполнения

**Типичное время:** 5-30 секунд

**Факторы:**
- Размер статьи (загрузка страницы)
- Скорость GigaChat API
- Скорость сети

**Влияние:** Пользователь ожидает ответ 5-30 секунд.

### Масштабируемость

**Ограничение:** Один workflow instance.

**Влияние:**
- Ограниченное количество одновременных запросов
- Блокирующее выполнение

**Возможное улучшение (не в MVP):**
- Horizontal scaling n8n
- Queue system (Redis)
- Load balancing

## Безопасность

### Credentials

**Ограничение:** Credentials хранятся в PostgreSQL в зашифрованном виде.

**Влияние:**
- Credentials не в plain text
- Но могут быть извлечены при доступе к PostgreSQL

**Решение:** Документирование требований к безопасности PostgreSQL.

### Rate Limiting

**Ограничение:** Нет rate limiting для пользователей.

**Влияние:**
- Один пользователь может отправить много запросов
- Возможен DoS

**Возможное улучшение (не в MVP):**
- Rate limiting по chat_id
- Queue для обработки запросов

## Рекомендации по обходу ограничений

### Для длинных статей

- Увеличьте `MAX_TEXT_LENGTH` (но учтите лимиты GigaChat)
- Предупредите пользователя о возможном усечении

### Для разных сайтов

- Добавьте новые CSS-селекторы в `Extract Article`
- Добавьте новые stop markers в `Clean Text`

### Для production

- Используйте webhook вместо polling
- Настройте HTTPS
- Настройте мониторинг
- Настройте бэкапы

### Для высокой нагрузки

- Используйте Redis для кэширования токена GigaChat
- Переключите n8n в queue mode
- Используйте load balancer для n8n instances
