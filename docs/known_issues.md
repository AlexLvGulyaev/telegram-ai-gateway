# 🚨 Telegram AI Gateway · Known Issues

Документ описывает известные проблемы проекта Telegram AI Gateway и возможные обходные пути.

## 🚨 1. Проблемы извлечения текста

### Проблема: Не все статьи извлекаются корректно

**Симптом:** Бот возвращает "Не удалось извлечь текст из статьи" для статей, которые должны извлекаться.

**Причины:**
- Разная структура HTML на разных сайтах
- JavaScript-рендеринг контента
- Защита от парсинга (CAPTCHA, rate limits)
- Динамические ключи в JSON

**Обходной путь:**
- Добавьте новые CSS-селекторы в ноду `Extract Article`
- Проверьте, что сайт не требует JavaScript
- Используйте сайты с простой структурой HTML

**Статус:** Не будет исправлено в MVP. Требует улучшения CSS-селекторов.

### Проблема: Извлекается мусор (навигация, реклама)

**Симптом:** Текст содержит навигационные элементы, рекламу, ссылки.

**Причины:**
- Stop markers не покрывают все разделы
- Regex-паттерны слишком мягкие
- Разная структура разных сайтов

**Обходной путь:**
- Добавьте новые stop markers в ноду `Clean Text`
- Ужесточите regex-паттерны
- Используйте сайты с чистой структурой

**Статус:** Частично решено stop markers. Требует улучшения для конкретных сайтов.

## 🚨 2. Проблемы GigaChat API

### Проблема: GigaChat возвращает ошибку авторизации

**Симптом:** Бот возвращает "Ошибка авторизации в сервисе".

**Причины:**
- Неверный `client_id` или `client_secret`
- Истёк срок действия credentials
- Неверная Base64 кодировка

**Обходной путь:**
- Проверьте credentials на developers.sber.ru
- Проверьте Base64 кодировку: `echo -n "client_id:client_secret" | base64`
- Убедитесь, что scope `GIGACHAT_API_PERS` активен

**Статус:** Требует правильной настройки credentials.

### Проблема: GigaChat API возвращает 500/502/503

**Симптом:** Бот возвращает "Сервис временно недоступен".

**Причины:**
- Перегрузка GigaChat API
- Технические работы
- Rate limiting

**Обходной путь:**
- Retry с exponential backoff (реализовано)
- Подождите несколько минут
- Попробуйте позже

**Статус:** Retry реализован. Полное решение требует мониторинга.

### Проблема: GigaChat генерирует разный контент

**Симптом:** Разные запуски для одной статьи дают разный результат.

**Причины:**
- Температура модели (даже 0.1 даёт вариативность)
- Вероятностная природа генерации

**Обходной путь:**
- Установите температуру 0 для полной детерминированности
- Ужесточите промпт
- Используйте одинаковый system prompt

**Статус:** Ожидаемое поведение модели. Детерминированность не гарантируется.

## 🚨 3. Проблемы Telegram API

### Проблема: Telegram rate limit

**Симптом:** Бот не отправляет сообщения после нескольких запросов.

**Причины:**
- Превышение лимита 30 сообщений/секунду
- Много частей сообщения отправляются быстро

**Обходной путь:**
- Добавьте задержку между отправками частей
- Не отправляйте много запросов одновременно
- Используйте webhook вместо polling

**Статус:** Retry для отправки не реализован. Требует добавления задержки.

### Проблема: Bot заблокирован пользователем

**Симптом:** Бот не может отправить сообщение.

**Причины:**
- Пользователь заблокировал бота
- Пользователь удалил чат

**Обходной путь:**
- Проверьте логи на ошибки Telegram API
- Игнорируйте ошибки отправки для заблокированных пользователей

**Статус:** Обработка ошибки реализована (continue on fail).

## 🚨 4. Проблемы n8n

### Проблема: Workflow не активируется

**Симптом:** Переключатель Active не включается.

**Причины:**
- Отсутствуют credentials
- Неверные credentials
- Ошибки в нодах

**Обходной путь:**
- Проверьте все credentials в n8n UI
- Проверьте каждую ноду отдельно
- Проверьте логи n8n

**Статус:** Требует правильной настройки.

### Проблема: Workflow зависает

**Симптом:** Workflow выполняется бесконечно.

**Причины:**
- Использование `Send and Wait` вместо `Send Message`
- Зависание HTTP Request ноды
- Отсутствие timeout

**Обходной путь:**
- Используйте `Send Message` вместо `Send and Wait`
- Установите timeout для всех HTTP Request нод
- Проверьте логи n8n

**Статус:** Timeout установлен для всех HTTP Request нод.

### Проблема: n8n не запускается

**Симптом:** Контейнер n8n не запускается или сразу останавливается.

**Причины:**
- Порт 5678 занят
- PostgreSQL не запущена
- Неверные credentials
- Недостаточно ресурсов

**Обходной путь:**
- Проверьте порт: `sudo netstat -tlnp | grep 5678`
- Проверьте PostgreSQL: `docker compose ps postgres`
- Проверьте логи: `docker compose logs n8n`
- Увеличьте ресурсы VPS

**Статус:** Требует диагностики в каждом конкретном случае.

## 🚨 5. Проблемы сети, производительности и безопасности

Эти темы — одновременно ограничения платформы; их владелец содержания — [limitations.md](limitations.md) (§5 Сетевые ограничения, §6 Производительность, §7 Безопасность). Сводка проблем с точки зрения эксплуатации:

| Проблема | Симптом | Обходной путь |
|----------|---------|---------------|
| Требуется VPN | Бот не работает без VPN (блокировка Telegram/GigaChat/целевых сайтов) | Системный VPN; браузерный не работает для Docker; VPS в доступном регионе |
| Webhook не работает | Telegram не отправляет обновления | HTTPS с Let's Encrypt, проверка `WEBHOOK_URL`, порт 443; fallback — polling |
| Долгое выполнение | Ответ через 30+ секунд на больших статьях | Уменьшить `MAX_TEXT_LENGTH`/`MAX_PROMPT_LENGTH`; ожидаемое поведение для больших статей |
| Потребление памяти | n8n потребляет много памяти | Очистка execution history, периодический перезапуск, увеличение памяти VPS |
| Credentials в логах | Credentials видны в логах n8n | Не логировать credentials, ограничить доступ к логам |

Диагностика по симптомам — [deployment_guide.md](deployment_guide.md), раздел Troubleshooting.
