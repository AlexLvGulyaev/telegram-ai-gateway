## 1. Ответ на задание PEn01

### 1.1 Из чего состоит MVP на основе ИИ

MVP — минимально жизнеспособный продукт для проверки гипотезы.

**Реализация в проекте:**

| Блок | Роль | Технология |
|------|------|------------|
| **Оркестратор** | n8n связывает компоненты | Telegram Trigger → Load Page → GigaChat → Send Message |
| **Мозг (LLM)** | Понимает текст, формулирует ответ | GigaChat API (Chat Completions) |
| **Данные** | Хранит логи выполнения | PostgreSQL (workflow_logs) |

n8n — визуальный конструктор, связывающий Telegram Bot API, GigaChat API и PostgreSQL без кода.

### 1.2 Сценарий для ИИ-MVP

**Задача:** Автоматизировать переработку статей в структурированные посты для Telegram.

**Пользователь:** Контент-менеджер, редактор Telegram-канала, автор.

**Результат:** Пользователь отправляет URL статьи → получает готовый структурированный пост через 5-30 секунд.

**Пользовательский сценарий:**

1. Пользователь отправляет ссылку на статью в Telegram-бота
2. Бот загружает статью, очищает текст, генерирует пост через GigaChat
3. Бот возвращает структурированный пост
4. При ошибках — бот информирует пользователя понятным сообщением на русском

### 1.3 Схема workflow в n8n

Линейный pipeline с обработкой ошибок:

```
Telegram Trigger → Load Page → Extract Article → Clean Text → GigaChat → Send Message
```

Каждый этап имеет error handling:

- Invalid URL → Send Error (Invalid URL)
- Load Page Error → Send Error (Load Failed)
- Auth Error → Send Error (Auth Failed)
- API Error → Send Error (API Unavailable)

**Детальная схема:** https://github.com/AlexLvGulyaev/telegram-ai-gateway/blob/main/docs/workflow_overview.md

### 1.4 Способ запуска n8n

| Способ | Плюс | Минус | Подходит для |
|--------|------|-------|--------------|
| **Локально (npx)** | Быстрый старт | Данные на компьютере, не 24/7 | Обучение |
| **Docker Desktop** | Изоляция | Требует Docker | Разработка |
| **Сервер (VPS)** | 24/7, контроль данных | Настройка, оплата | Production |

**Выбор для проекта:**

- **Для обучения:** Локальный запуск через Docker Desktop
- **Для production:** Серверный запуск на VPS через Docker Compose

**Обоснование:** При выборе архитектуры учитывались требования к контролю персональных данных. Серверный вариант выбран как более подходящий для сценариев, где требуется контролировать место хранения и обработку данных.

**Конфигурация:** https://github.com/AlexLvGulyaev/telegram-ai-gateway/blob/main/docs/deployment_guide.md

### 1.5 Требования по данным

**Облачный n8n не подходит** для сценариев с персональными данными, поскольку данные хранятся за пределами РФ.

**Выбранный способ:** Серверный запуск на VPS (Beget) с PostgreSQL.

**Меры безопасности:**

- `.env` файл в `.gitignore`
- Секреты не коммитируются в GitHub
- Credentials хранятся в зашифрованном виде
- Basic Auth для доступа к n8n UI

### 1.6 Итоговый вывод

1. **No-code в ИИ** позволяет одному человеку собрать ИИ-продукт за несколько дней вместо нескольких недель.

2. **MVP лучше собирать быстро** для проверки гипотезы. Telegram AI Gateway собран за 2 дня и сразу протестирован.

3. **n8n удобен как оркестратор** — связывает Telegram Bot API, GigaChat API и PostgreSQL без кода.

4. **Для проекта выбран серверный запуск** через Docker Compose на VPS, что позволяет контролировать место хранения и обработку данных.

5. **Проект развился сверх MVP** — от простого бота до инженерной реализации с обработкой ошибок, логированием, retry-механизмами и документацией.

### Обработка ошибок и информирование пользователя ✅

Добавлены IF-ноды для проверки на каждом этапе (Check URL, Check Load Error, Check Text, Check Token, Check Response) с пользовательскими сообщениями на русском языке. Реализована обработка DNS, timeout, SSL, HTTP ошибок (404, 403, 500).

**Документация:** https://github.com/AlexLvGulyaev/telegram-ai-gateway/blob/main/docs/workflow_overview.md

### Логирование ✅

Создан отдельный Log Writer workflow для записи логов в PostgreSQL. Request ID обеспечивает корреляцию логов одного запроса. Все критические этапы логируются.

**Документация:** https://github.com/AlexLvGulyaev/telegram-ai-gateway/blob/main/docs/logging-integration-guide.md

### Retry-механизмы ✅

Реализованы retry-политики для HTTP-запросов: Load Page (3 попытки), Get GigaChat Token (2 попытки), GigaChat API (2 попытки).

### Ограничения длины ✅

Настроены лимиты: MAX_TEXT_LENGTH (12000), MAX_PROMPT_LENGTH (5000), MAX_MESSAGE_LENGTH (4096). Split Message node разбивает длинные сообщения с нумерацией.

### Конфигурация ✅

Configuration node с 27 параметрами: LLM Configuration, Limits, HTTP Settings, User Messages. Все секреты вынесены в `.env` файл.
